        AGENT GRAPH

        一次提问实际经过的节点

        LangGraph 有界图：8 个节点、最多两轮检索；decide 决定要不要查资料，evidence 决定要不要补查。

        • 01
          context取本请求之前成功完成的问答，最多 12 轮、12000 字符预算。
        • 02
          decide输出 direct / clarify / retrieve；判据是项目里有没有资料。
        • 03
          retrievepgvector 召回 20 个候选，cross-encoder 重排取 3 个。
        • 04
          evidence核对关键条件是否覆盖；缺证据才进 rewrite 补查，最多一轮。
        • 05
          rewrite只针对缺口写一条新查询；同查询或无新命中不重试。
        • 06
          answer只依据本轮片段作答，结论紧邻标注 [S1] 等真实编号。
        • 07
          validate剥掉不在来源集合里的引用；有资料却无有效引用就改为提示。
        • 08
          verify逐句比对结论与被引片段的词面重叠，过低则追加依据不足警告。
        ORCHESTRATION

        编排流程

        同一会话同一时刻只跑一个请求，跨会话并行。Redis 只搬信号，业务真相始终在 PostgreSQL。

        正常路径 Redis 投递 排队与超时恢复

        队列信号丢失不会丢任务：dispatched 状态留在 PostgreSQL 里，reaper 扫描到时按同样路径重新投递。

        SECURITY

        先把危险输入挡在门外

        Prompt 注入检测先做 NFKC、去零宽、大小写归一，再匹配中英文指令覆盖话术；同一身份每分钟 10 次，超限直接 429。

        • 命中直接 400，不落库、不回显攻击原文
        • Redis Lua 原子滑动窗口，多副本共享计数
        • audit_logs 只记 rule_id 与 retry_after
        边界只拦已知话术，不承诺防语义改写
        切换标签查看四层能力 · 切换即重播
        SECURITY

        输入先过闸

        NFKC / 零宽 / 中英文规则；Redis Lua 限流；audit_logs 留痕。命中不落库。

        COST

        成本有账本

        复用模型 usage，逐轮记录输入/输出/调用次数；单价按模型预填，按身份隔离。

        HEALTH

        worker 掉线可见

        心跳写入 Redis、15 秒 TTL；/ready 同时报告 worker 与队列积压，未就绪返回 503。

        RECOVERY

        断点续传

        PostgresSaver 按「会话:请求」保存状态；worker 重启后从最后 checkpoint 续跑。

        QUALITY

        引用与回归

        逐句检查 [S#] 依据；20 题检索回归接入 CI，Hit@1 / MRR@3 / Recall@3 不倒退。

        DELIVERY

        可交付的工程

        CI 同时跑后端测试、前端 SSE 测试与构建，以及真实 PG/Redis 的集成用例。

        工程侧回归：20 题 Hit@1 1.0、MRR@3 1.0、Recall@3 1.0（阈值 0.85 / 0.90 / 0.95）；CI 门禁脚本为 evaluation/regression.py。
        HIGHLIGHTS

        关键设计与实测

        两个关键设计，外加一组公开数据集实测：THUIR/T2Ranking dev split，300 条查询，走生产入库与检索通道。

        亮点一 · 自主决策检索

        先想「要不要查」，再决定怎么答

        项目非空时，凡涉及主题、概念、命令或做法的提问一律先 retrieve； 只有问候寒暄、改写用户粘贴的文本、问助手自身三类才 direct。项目为空则不会空跑检索。
