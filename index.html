    为什么这样设计

    核心能力

    把并发、恢复、可追溯这三件难事，在一条请求链路上做扎实。

    ⚡

    落库即返回

    提问先把 Message 与 AgentRunRequest 写进 PostgreSQL，拿到 request_id 立即返回；慢的模型执行交给后台 worker，接口始终轻快。

    🔑

    三元组 FIFO 串行

    同一 (用户, Agent, 会话) 严格串行、不同组并行。派发前取 advisory 组级锁，只有 ready 队头才创建 AgentRun。

    ♻

    崩溃自动恢复

    worker 抢租约转 running，每 2s 心跳续约；进程崩了心跳停更，reaper 每 5s 扫超时租约打回 pending 重投。

    📡

    SSE 流式 + 晚连补读

    答案逐字实时推送；即便客户端在执行完成后才连上，也能靠 request_id 补读完整结果。

    🔍

    命中出处可追溯

    回答前先给出命中的资料片段，答案基于真实检索结果生成，而非模型凭空作答。

    🎯

    两阶段检索 + 评测

    向量召回 top-20 后，接 cross-encoder 逐对精排取 top-3。用公开中文基准 T2Reranking 量化重排收益与延迟代价。
